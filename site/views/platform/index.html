Can my teams build on this registry, and on these addresses?

You already trust digests: an image pulled by @sha256 is the image you tested. Prism takes the same idea one level up. The decisions your platform makes about those digests are themselves content-addressed apps, and their rules are proved, not just tested.

Walk it

  1. Warnings only: the registry is conformant and CI stays green.

    conformance-verdict ok reachable 0 3 model answer: conformant

  2. Two MUST failures: nonconformant, exit code 1.

    conformance-verdict ok reachable 2 0 model answer: nonconformant

  3. A sha512 label with 64 digits is refused: sha512 needs 128.

    kappa-label-check sha512 1 lower 64 model answer: deny

The decisions behind this view

Conformance verdict

Decision table (OMG DMN 1.5, hit policy FIRST) · grounded in UOR-Foundation/kappa-distribution

Tell a platform team, from one run of the kappa-conformance binary, whether their registry is ideal, conformant or not, and what exit code CI sees.

A request is config (whether KAPPA_REGISTRY_URL and the other required variables were set), network (whether the registry under test answered), must (MUST tests that failed), should (SHOULD tests that warned), in that order.

Promises the Lean kernel proves for every request

  • It never answers ideal when must > 0: a MUST failure is never ideal.
  • It never answers conformant when must > 0: a MUST failure is never conformant.
  • It always answers conformant when config is ok and network is reachable and must <= 0 and should > 0: warnings alone never fail a reachable, configured run.

Kappa-label check

Policy decision (OASIS XACML 3.0) · grounded in UOR-Foundation/kappa-distribution

Decide if a string is a well-formed kappa-label, the content address every kappa-distribution object is named by, before anything trusts it.

A request is axis (the sigma-axis token before the colon), colons (how many colons the label holds), hex (whether every digest character is 0-9 or a-f), digits (how many hex digits follow the colon), in that order.

Promises the Lean kernel proves for every request

  • It never answers permit when axis is other: an unrecognized sigma-axis is never admitted.
  • It never answers permit when hex is other: an uppercase or non-hex digest is never admitted.
  • It never answers permit when digits < 64: no admitted label is shorter than 32 digest bytes.
